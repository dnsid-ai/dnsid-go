# docs/ Guidelines

Rules for anyone — human or agent — touching files under `docs/`.

## What this directory is

`docs/reference/` is the generated markdown API reference for the Go SDK. It is
exported verbatim to the docs site repo `dnsid-ai/dnsid-docs` under
`src/content/docs/reference/go/` (rendered at https://docs.dnsid.ai/reference/go/…),
and it also renders directly on GitHub. `docs/reference/nav.json` is an ordered
nav fragment imported by that site's `nav.mjs`.

## Rules

- **Never hand-edit files in `docs/reference/`.** They are generated by
  [`scripts/gen-docs.sh`](../scripts/gen-docs.sh) (gomarkdoc, pinned version) from
  the Go doc comments. To change a page, change the doc comment in the source and
  regenerate:

  ```sh
  ./scripts/gen-docs.sh
  ```

  CI fails if `docs/reference/` is stale relative to the doc comments (docs job in
  `.github/workflows/test.yml`).
- The directory is **committed**, so regenerated output shows up as reviewable
  diffs in normal PRs. Commit the regenerated files together with the doc-comment
  change that caused them.
- Every page must keep YAML frontmatter with `title` (e.g. `Go: package oidc`)
  and a one-line `description`, plus a link to its pkg.go.dev counterpart as the
  canonical deep reference. The generator emits all of this; if you change the
  page shape, change the generator.
- Links to docs-site pages must be **absolute** `https://docs.dnsid.ai/...` URLs,
  never site-relative slugs — these files render both on GitHub and on the docs
  site, and relative slugs break on GitHub. (This applies to Go doc comments too,
  since they flow into these pages.)
- Adding or removing a public package? Update the `PACKAGES` table in
  `scripts/gen-docs.sh` (page slug, nav label, description) so the page and its
  `nav.json` entry are generated.

## Terminology

Match README.md / QUICKSTART.md usage: "DNSid" (capital DNS, lowercase id),
"identity record", "operational key" / "entity key", "agent". Doc comments (and
therefore these pages) describe behavior and contracts, not implementation
history.
